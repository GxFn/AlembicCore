# 图与证据规范

每页 frontmatter 是节点、边、来源和断言的唯一正典。中文正文解释入口、输入输出、owner、真实消费者、副作用、失败恢复和限制；下方生成的 Mermaid/证据表与浏览器消费同一模型。

## 关系含义

| 视图 | 可以说明 | 不可以推断 |
| --- | --- | --- |
| A0/A1 | 包/事实责任与边界 | 导入即执行 |
| V0/F1 | 已指定业务场景和源码关系 | 宿主必然自动串接所有服务 |
| F0 | 精选静态导入图；完整导入数据在data | 运行调用、测试覆盖、动态引用不存在 |
| S0/R0 | owner控制的状态与恢复分支 | 全链原子事务或未声明的自动重试 |
| E0/D0 | 验证来源、变更复核候选 | 产品验收或实际发布完成 |

节点role驱动配色；未知role使用中性色，不能通过名称关键字猜测权威。节点/边均用稳定ID，源定位使用仓库相对路径加真实声明符号，行号仅辅助。每图提供中文accTitle与accDescr；默认阅读模式保持字形，超宽时拖动平移，“全图”单独操作。

## 状态与来源

`truthKind`区分current-code、in-progress-worktree、historical、target-design、stale；观测到的source-drift/context-drift不能被手写current覆盖。L0库存、L1定位、L2局部读取、L3所画关系逐边复核、L4运行场景、L5外层验收是不同深度。本版专题L3不宣称L4/L5。

source路径与字节共同参与指纹，输入缺失、空glob和symlink不接受。配置、测试和消费者构成上下文摘要。public-api和层矩阵的权威始终是Core既有配置。复制到独立机器且缺少ledger或消费者仓库时，必须显示来源不可重新核验。

## 断言关系

- direct：case内实际调用的符号/方法解析到生产定义，并有断言；它仍需要人工理解assertedBehavior。
- indirect：fixture/helper或间接观察，记录真实case和断言片段，不能冒充直接调用。
- none：必须说明未覆盖原因；无覆盖通过的是诚实性检查，不是产品测试。

测试只import、注释提名、同名局部变量均不能算direct。检查器只能验证结构/身份/断言归属；业务语义仍需人工逐边复核。原产品测试、静态检查、实际SVG渲染、Cytoscape和阅读交互分开记录。
