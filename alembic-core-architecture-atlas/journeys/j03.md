本旅程按输入、分母、真实执行、观察、机制和假设组织阅读。步骤中的 call 只指明所列 Core 入口内部发生的真实调用；data/binding 是调用者显式提交同一条谱系材料；host-action 不在 Core 中实现。

普通计划投影可用于任务选择，严格计划还必须拥有完整 required applicability 和冻结 subject。compiler 生成 schedule 的行为与执行 schedule 的行为是两个入口。population、cluster、induction、falsification 都是对已提供材料进行规范与验证的构造器，不会自行做 Analyst/Producer/Reviewer 的模型工作。

发生 unknown 或错误时保留分母和原因，从对应 failure 条目进入恢复。扩大输入、改变源码revision或修改语义提案，应更新该版本谱系与独立review，不应只重写hash。统一authority的全链重验见专题15，但没有外层接线证据时不能把它画成所有发布路径的必经调用。
