## 先辨认五个不同的成功

创建完成意味着普通知识服务返回实体；同步完成意味着本次文件扫描和 DB 投影结束；向量维护完成意味着该向量端口的工作已经结束；发布完成意味着指定生命周期操作成功；一次可查询结果还需要候选召回、live truth 和过滤预算一起满足。五者不能互相替代。

## 如何沿旅程阅读

01–04 是普通创建中的真实调用层次。05 是文件/DB 分歧或手改文件时由宿主选择的恢复支路。06 是另一次显式生命周期动作，07 是 dense 检索的数据绑定接缝，08 才是查询路径。顺序帮助读者追踪状态，并不表示 Core 存在一个自动执行全部步骤的总函数。

## 出错以后先看什么

先用 entryId 核对 Markdown 与 DB，再查看 relations/audit/quality 等后置效果；随后核对 lifecycle 和 published metadata；最后检查向量活跃代际与查询 diagnostics。不要因为外层收到了 create_failed 或 syncAll reject，就假定底层全部回滚。

本页保留 DB-only 兼容模式、sync 逐文件跳过与后续孤儿检测、staging 两段发布等实际边界。严格 prepared admission 请沿 J03/J04 阅读。
