# 向量快照与恢复职责

ASVEC 继续使用 v1 布局。公开 package 入口、节点 ID、Float32 向量、metadata/contents
映射及已有排序策略保持兼容。格式、模型可用性与恢复时序由不同模块负责。

| 模块 | 责任 |
| --- | --- |
| BinaryPersistence | 统一快照输入、编码/解码、布局和引用边界、完整文件的原子替换 |
| HnswVectorAdapter | 原始向量/图恢复、当前量化配置、初始化、WAL 和迁移的执行顺序 |
| ScalarQuantizer | 单一维度模型的训练和 SQ8 编码；不决定宿主配置或快照归档 |
| VectorMigration | 读取旧 JSON，等待迁移回调成功后归档；保留原数组/对象格式 |

## 一处判定可读性

load 调用 decode；isValid 也复用该解码判定。魔数正确不能证明整个快照可读。
解码在分配和遍历前检查各段计数对应的字节范围，并检查 entry point、图节点/邻居
和图层引用。Adapter 的两种初始化使用同一个恢复入口，只读取/解码快照一次。

保留旧格式的容错边界：metadata 段可以省略；完整但无法解析的 metadata JSON
仍按原规则忽略；metadata/contents 可以含有不在 ANN 节点中的关键词条目。
删除高层节点后遗留的空图层合法，不要求 header 层数与存储图层数相等。
这些结构检查不等于内容校验和或 ANN 质量验证。

## 写入与归档顺序

save/saveAsync 都先在同目录写唯一临时文件，完成后再 rename 发布。部分写入或
发布失败会保留旧目标并清理本次临时文件，原始异常继续传播。覆盖旧快照时，
临时文件在正文写入前继承旧文件 mode；首次创建维持既有默认 mode。
WriteZone 路径继续经过其写入/重命名约束。

这是普通快照路径的原子替换，会替换目录项/inode，需要目录可写；不提供任意链接、
ACL 或 inode 身份保持协议，也没有新增 fsync 断电耐久保证。

含有效条目的旧 JSON 只有在迁移数据已写成新快照后才归档为 .bak。读取/解析失败仍按旧规则
降级；目标存储失败必须向调用方传播并保留 JSON。同步初始化也遵守这个区分，
不能把保存失败解释为 JSON 解析失败或初始化成功。WAL 恢复后的写盘错误继续
在快照读取容错范围之外传播。

## 量化是可选加速状态

quantize:none 重开含模型的快照时仍使用原始向量，不能被文件中的模型覆盖配置。
正维度且与向量维度相符的已训练模型才写入快照。历史空索引可能携带零维模型，
其文件仍可读取；Adapter 忽略该加速模型并保留其余数据，后续写入按原训练规则
重建模型。既有训练阈值、两阶段搜索和精排策略不变。

旧的“quantize:none 然后数 ID”测试不能证明量化恢复。HnswVector.test.ts 现在验证
真实 SQ8 编码与重开后的查询次序；VectorPersistence.test.ts 验证格式、故障保存和
v1 兼容；宿主继续通过包入口验证自己的只读读取和服务接线。
